# 요구사항 정의서

## 1. 목적과 범위

운영자가 두 로봇의 위치와 실시간 영상을 동시에 보고 마스터에게 이동 임무를 부여하며, 슬레이브의 추종 상태를 확인하고 이상 발생 시 대응할 수 있게 한다. 추종 궤적 생성, 장애물 회피, 모터 제어는 로봇 측 담당이다. 관제는 상태 수집, 명령 전달·결과 확인, 알림, 운용 이력을 담당한다. 카메라 영상 녹화와 동기 재생은 범위에서 제외한다.

운영자는 제어권을 획득해 임무·수동 조작을 수행한다. 관찰자는 실시간 상태와 운용 이력만 조회한다. 관리자는 로봇 연결 정보와 제한값을 설정한다. 단일 사용자 개발 환경에서도 서버 권한 검증은 동일하게 적용한다.

## 3. 비기능 요구사항 및 시험 목표

기준 부하: 관제 PC 1대, 로봇 2대, 브라우저 1개, 동일 LAN, 지도 최대 2048×2048셀. 하드웨어 정보와 네트워크 상태를 시험 보고서에 남긴다.

| ID | 요구사항/목표 | 측정 방법 |
|---|---|---|
| N01 | 위치·편대 화면 갱신 5Hz, 서버 수신→화면 p95 300ms 이하 | 10분간 timestamp 계측. 센서 원본이 느릴 때는 원본 주기도 함께 기록 |
| N02 | 영상 2개 각 640×480, 목표 10FPS, 촬영→화면 p95 800ms 이하 | 시계 동기화 확인 후 화면 시계 촬영 시험. 동기화 불명 시 종단 지연은 측정 불가로 표시 |
| N03 | 제어 HTTP 응답 p95 300ms 이하, 로봇 수락 2초 제한 | 영상 동시 표시 중 100회 모의 명령 및 실물 정지 상태 명령 시험 |
| N04 | 위치 1초, 로봇 heartbeat 3초, 영상 2초, 배터리 15초 경과 시 stale | 타입별 가짜 시계 테스트. 배터리의 기존 5초 발행 주기 반영 |
| N05 | 단절 후 재연결 시 최신 전체 스냅샷 복구, 주행 자동 재개 금지 | 브라우저·서버·로봇 각각 끊고 복구 시험 |

| N08 | 한국어 UI, 1366×768 이상 PC 우선, 900px 미만 영상 1열 | 지도 아래 그리드 순서 유지, 키보드 포커스 및 색상 외 상태 텍스트 검사 |

## 4. 정상 운용 시나리오

로그인 → 로봇·지도·센서 상태 확인 → 제어권 획득 → 두 로봇 초기 위치 확인 → 편대 연결 → 슬레이브 추종 준비 확인 → 마스터 목표 선택 → 시작 → 지도와 영상 및 간격 확인 → 양쪽 도착·정지 확인 → 임무 이력 확인.

단일 로봇 시험은 편대 연결 없이 선택 로봇을 정지시킨 뒤 지도에서 시작점·방향과 도착점·방향을 지정하고 명시적으로 실행한다. 시험 중 로봇을 손으로 들어 다른 위치에 놓으면 전체 정지와 정지 확인 후 새 시작점을 지정하고 `AMCL 위치 재설정`을 수행한 다음, 정지 해제를 별도로 확인하고 새 도착점 주행을 요청한다. 이 과정은 현장 world와 일치하는 정적 점유 지도를 유지한다.

슬레이브 이탈·통신 단절이 발생하면 편대 임무를 일시정지하고 두 로봇에 정지를 요청한다. 복구 후 자동 출발하지 않는다. 운영자가 원인을 확인하고 재합류 또는 임무 재개를 선택한다.

## 5. 담당 경계와 실물 연동 조건

실물 배포는 `robot_1`의 ROS_DOMAIN_ID 12와 `robot_2`의 ROS_DOMAIN_ID 13을 고정한다. 관제 UI/API는 domain ID 변경을 제공하지 않으며, rosbridge URL과 토픽·서비스·카메라 매핑만 배포 설정에서 지정한다.

YYM 현장 운용에서는 제한된 Wi-Fi 대역폭을 주행·라이다·TF에 우선 배정하기 위해 두 로봇의 카메라 발행과 관제 구독을 비활성화한다. 카메라 기능 요구사항은 제품 범위에 유지하되 이 배포 프로필에서는 노출하지 않는다.

| 담당 | 납품물 |
|---|---|
| 관제 담당 | 웹 UI, API, ROS 어댑터, 영상 중계, 모의 데이터, 기록·알림·테스트·실행 문서 |
| 마스터/내비게이션 담당 | 목표 action, 진행·결과, 위치/TF, 정지 및 모드 전환 계약 구현 |
| 슬레이브/추종 담당 | 추종 상태·오차·준비 응답, 시작/해제/재합류, 로컬 장애물 회피 |
| 공동 연동 | namespace/TF, 시간 동기화, 카메라 매핑, 구동 명령 중재·watchdog, 실물 정지 시험 |

실물에서 계약을 제공하지 않으면 해당 제어는 `UNSUPPORTED`로 표시한다. 관제 모의 구현은 계속할 수 있지만 실물 완료 판정은 보류한다. 실물 카메라 주소·타입은 자동 추측으로 고정하지 않고 발견 결과를 설정 파일에 기록한다. 정적 지도 기반 주행은 Nav2 AMCL과 `NavigateToPose` 계약 및 로봇 측 watchdog이 모두 준비된 경우에만 활성화하며, 관제의 지도 클릭만으로 자동 주행이 시작되지 않게 한다.
